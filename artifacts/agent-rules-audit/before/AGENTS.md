## 全局协作规则

### 权限与沙盒问题

- 如果 Codex 遇到沙盒审批超时、拒绝访问、无法写入 `D:\0-Codex\CodexData\...` 等权限问题，不要反复申请权限。
- 第一时间让用户在“管理员: Windows PowerShell”里操作。
- 给用户提供可直接复制粘贴的完整路径命令。
- 用户执行后，如果没有红色报错并返回 PowerShell 提示符，通常视为成功；必要时再检查目标文件。

### 常驻服务与本地预览

- `npm run dev`、`vite --host`、`python -m http.server`、本地 HTTP 服务等属于常驻进程，必须短超时（不要超过5分钟）、少尝试（可尝试，但次数不要超过3次）、及时止损。
- 如果测试和生产构建已经通过，应优先交付结果，不要为了启动预览服务反复消耗用户等待时间（可以启动预览服务，但如果失败超过两次的话就不要勉强了）。
- 在 Windows/Codex 沙箱里，如果遇到 `esbuild spawn EPERM`、端口占用、后台进程无输出等环境问题，不要反复重试同类命令。
- 预览服务启动失败时，应明确说明：“代码测试/构建已通过，预览服务受当前沙箱或本机环境限制未启动。”
- 除非用户明确要求继续排查预览环境，否则不要把 dev server 成功启动作为交付前置条件。

### 交付与止损

- 当核心任务已完成，并且必要测试或构建已经通过，应及时交付结果。
- 如果某一步属于环境验证、预览体验、权限安装或非核心增强，失败时应说明影响范围，而不是阻塞主任务。
- 长时间（超过10分钟）无输出的命令应主动设置超时或中止，并向用户说明当前状态。
- 遇到权限、常驻进程、外部服务、网络连接等非代码问题时，应优先给用户清晰的下一步操作，而不是在后台反复试错。
- 小改动小验证：非核心小改（文案/样式/单行逻辑）默认只跑最小必要验证（定向脚本或一次快速检查），禁止为其启动全量/长耗时集成测试；仅当改动触及核心链路或用户明确要求时才升级测试范围。

# AGENTS.md 与 Skills 审阅和优化

## 结论与范围

高成本主要来自通用流程技能的叠加，而不是缺少更强的措辞。优化采用明确目标、保留约束、按风险验证、避免重复审批的方式，为用户指定的 GPT-6 Astra 留出实施判断空间；不修改模型、推理强度、沙箱或账号配置，不声称某种固定 Token 降幅。

本次扫描 25 个个人技能入口和实际生效的全局 AGENTS.md，重点精读通用开发流程与触发的冲突段落。对照读取了官方 openai-docs、skill-creator 入口；未逐篇审阅全部插件缓存、示例角色和工具实现。`inventory.json` 保留本次个人技能扫描路径与命中行，`before/` 保存16个拟修改文件的原始字节。没有更改网站业务代码。

## 交付文件

- `after/AGENTS.md`：全局规则精简稿。
- `after/` 其余15个文件：14个通用流程技能精简稿，加storage-analyzer定点修正。
- `before/`：完整原版备份，不自动加载为技能。
- `manifest.json`：目标绝对路径、修改前后SHA256和文件大小。
- `install.ps1`：默认仅检查；`-Mode Apply`应用，`-Mode Restore`恢复本包原始版本。目标有后续编辑时拒绝覆盖。

保留所有技能名称和目录，已有脚本、模板和其他资源不删除。专业制作技能继续保留其质量要求；本次没有通过修改插件缓存解决问题。个人技能将来重新安装可能覆盖本次入口文件，届时应重新核对差异，不能盲目重放旧快照。

## 代表场景检查

以下是规则对照检查，不是模型实测分数，不宣称已证明节省具体 Token。

| 场景 | 优化后的预期 |
|---|---|
| 按明确要求交换按钮位置 | 直接改，定向检查，不先写设计或启动子代理 |
| 修改答题次数统计 | 明确统计语义，测试已用/未用及当前场次边界，不让一行改动免除逻辑验证 |
| 已批准继承歌单，再要求增加按钮 | 复用授权，完成按钮、行为和最小验证 |
| 只要求设计方案 | 完成设计，不擅自实现或部署 |
| 审查有6项，其中2项不明 | 澄清2项，同时完成独立明确项 |
| 缺少不可推断的业务口径 | 提问等待必要答案，不把超时当批准 |
| 构建遇到spawn EPERM | 报告类型检查与构建的真实状态，停止同类重试，提供可执行下一步 |
| 用户只要求查磁盘占用 | 只扫描和出报告，不自行清理 |
| 用户明确指定可清理路径和方式 | 核对范围与权限；不为同一目标重复确认，仍不扩大操作范围 |
| 修改完成但没有PR请求 | 交付结果，不弹出固定四选一菜单 |
| 无权限修改全局配置 | 完成改稿、备份和脚本；明确尚未安装，不谎称全局生效 |

## 官方依据

个人AGENTS.md提供全局指令，技能按用途加载；配置变更后建议在新任务核对是否读入新内容。参考：[官方 AGENTS.md 指南](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[官方 Skills 指南](https://learn.chatgpt.com/docs/build-skills)。本次设计判断主要依据本机文件及本会话实际出现的重复审批，不以模型名称推导额外权限。

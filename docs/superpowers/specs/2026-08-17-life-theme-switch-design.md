# “生命万岁企划”双主题切换设计

日期：2026-08-17

## 1. 目标

在现有“JIEYOU 宇宙”基础上增加“生命万岁企划”。两个主题保持相同的基本交互、页面结构和响应式布局，但拥有独立的主题文案、强调色、音效配置与内容数据。

“生命万岁企划”用于记录生命中值得幸福、庆祝和铭记的时刻。用户通过点亮星星保存这些瞬间。

## 2. 已确认的产品决策

- 网站首先展示一个总入口页，两个主题平等呈现。
- 页面层级为：总入口 → 主题欢迎页 → 主题星空页。
- 用户昵称在两个主题间共享，切换时无需再次输入。
- 两个主题的星星、留言、数量统计、每日额度、搜索结果和主题成长进度互不共享。
- 主题星空页提供“切换企划”按钮，一步返回总入口页。
- 总入口采用两张并列主题卡片；移动端改为上下排列。
- 页面组件保持共用，通过主题配置产生两套主题体验，不复制两套大型组件。

## 3. 页面与切换流程

### 3.1 总入口页

新增 `ThemeHub`，作为应用打开后的默认页面。页面保留星空背景，展示两张地位相同的主题卡片：

1. JIEYOU 宇宙：延续当前紫色系和现有主题说明。
2. 生命万岁企划：使用暖金、日出橙作为强调色，说明“铭记生命里值得幸福的时刻”。

点击主题卡片后设置 `activeTheme`，进入该主题欢迎页。入口页可分别显示两个主题的星星数量；统计失败时显示“—”，不得使用另一主题的数量替代。

### 3.2 主题欢迎页

复用当前 `WelcomeScreen` 和 `NicknameInput` 的排版。主题配置决定标题、说明文字、功能亮点、按钮标签、强调色以及星星计数文案。

建议的“生命万岁企划”首版文案：

- 标题：生命万岁企划
- 引导语：愿每一份微小幸福，都被认真看见
- 欢迎卡片：欢迎来到生命万岁企划的第 N 颗幸福星星
- 说明：把今天值得庆祝的瞬间，留在这片属于生命的星空
- 进入按钮：进入幸福星空

若用户尚未输入昵称，点击进入按钮仍聚焦昵称输入框。完成输入后建立共享用户身份并进入当前主题星空页。

### 3.3 主题星空页

复用当前 `StarrySky`、`CreateStarModal`、搜索侧栏和星星详情组件。主题配置决定页头、CTA、提示语、颜色、声音和数据集合。

“生命万岁企划”建议使用：

- 页头：我们的幸福星空
- CTA：点亮幸福星星
- 创建提示：写下这个值得幸福的时刻
- 暖金与日出橙作为主要强调色

左上角现有“返回”按钮改为“切换企划”。点击后执行统一的 `returnToThemeHub`：

1. 关闭星星详情、创建弹窗、搜索侧栏和星宠面板。
2. 清空当前页面星星和临时交互状态。
3. 停止或重置主题专属声音。
4. 将 `activeTheme` 设为 `null`，将视图切回总入口。
5. 保留共享的 `user`，因此昵称不丢失。

## 4. 状态与组件架构

扩展 Zustand 应用状态：

- `activeTheme: 'jieyou' | 'life' | null`
- `currentView: 'theme-hub' | 'welcome' | 'starry-sky'`
- `user` 继续作为跨主题共享身份

新增主题配置类型 `ThemeConfig`，至少包含：

- 主题 ID、名称和短说明
- 欢迎页标题、引导语、卡片文字、功能亮点、CTA
- 星空页标题、创建 CTA 和提示语
- 主题强调色、按钮渐变和光晕颜色
- 背景音乐与音效映射
- 星星集合和星宠集合名称

新增或调整的主要单元：

- `ThemeHub`：总入口和两个主题统计。
- `themeConfig`：两份主题配置的唯一来源。
- `App`：管理总入口、主题欢迎页和主题星空页的状态流。
- `WelcomeScreen`：接收 `theme`，不再硬编码 JIEYOU 文案。
- `StarrySky`：接收 `theme`，不再硬编码标题、CTA 和服务集合。
- `starService` / `tcbService`：所有读取、创建、删除和统计操作必须显式接收 `themeId`。

组件内不得通过零散条件表达式重复主题文字。主题差异必须集中在配置文件中，避免两个界面逐渐失去一致性。

## 5. 数据隔离

采用“共享身份 + 独立内容集合”：

| 内容 | JIEYOU 宇宙 | 生命万岁企划 |
| --- | --- | --- |
| 用户身份 | `users` | 共享 `users` |
| 星星与留言 | `stars` | `life_stars` |
| 星宠进度 | `pet_stats` | `life_pet_stats`（启用对应功能时） |

这样无需迁移或修改现有 JIEYOU 星星。生命万岁从独立空集合开始。

所有主题数据操作必须遵守：

- 读取只访问当前主题集合。
- 新建只写入当前主题集合。
- 删除只操作当前主题集合。
- 数量、每日额度和搜索只统计当前主题集合。
- 切换主题前先清空界面缓存，再请求目标主题数据。
- 目标集合不可用时不得回退读取另一主题集合。

Supabase、自定义 API 和本地 mock 回退路径也必须携带主题信息或使用等价的隔离存储，不能只修复 TCB 路径。

## 6. 音频与主题表现

现有音频初始化由 `App` 管理。实现时应把背景音乐和点击音效来源改为主题配置，并在主题变化时安全切换：

- 进入主题前不自动播放新音乐，继续遵循浏览器的用户手势限制。
- 切换主题时暂停上一主题音乐，并更新音频源。
- 音乐开关状态可以共享，但实际播放曲目由当前主题决定。
- 生命万岁尚未指定专属音频时，可使用无音乐或明确配置的临时曲目，不能意外继承带有 JIEYOU 语义的语音。

## 7. 错误处理

- 切换后立刻清空旧星星；加载失败时显示空状态与重试入口。
- `life_stars` 不存在或无权限时显示“幸福星空暂时无法抵达”，不展示 JIEYOU 数据。
- 创建失败时移除乐观添加的临时星星或不进行乐观添加，并允许重试。
- 入口统计失败显示“—”。
- 主题配置缺失时回到总入口并显示错误提示，不能猜测默认集合。

## 8. 验证策略

### 8.1 单元测试

- 每个 `themeId` 映射到正确的数据集合。
- 主题配置包含界面所需的全部字段。
- `returnToThemeHub` 清理主题状态但保留用户。
- 每日额度和统计函数只处理当前主题。

### 8.2 组件与交互测试

- 总入口可以进入两个主题。
- 未输入昵称时仍执行原有聚焦行为。
- 已有昵称时切换主题不再次要求输入。
- 星空页“切换企划”一步回总入口。
- 两个主题往返切换后不显示上一主题星星或文案。

### 8.3 回归与构建验证

- 现有 JIEYOU 欢迎页、星空、创建、删除、搜索和星宠流程不退化。
- 桌面端、iPad 和手机端布局可用。
- TypeScript 检查和生产构建通过。

## 9. 非目标

本次不改变星星的核心创建字段、不重做星空布局、不增加第三个主题、不迁移现有 JIEYOU 数据，也不创建第二套用户账户系统。

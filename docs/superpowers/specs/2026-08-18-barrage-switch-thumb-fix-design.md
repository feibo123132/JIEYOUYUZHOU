# 弹幕开关白点定位修复设计

日期：2026-08-18

## 问题

“弹幕模式”和“亲密模式”的开关白点使用绝对定位，但没有水平锚点。关闭状态的 `translate-x-1` 和开启状态的 `translate-x-6` 因此从浏览器计算的静态位置开始移动，造成关闭时白点位于右侧、开启时越出开关边框。

## 修复

- 两个白点统一增加 Tailwind `left-0`，固定水平移动起点。
- 关闭状态继续使用 `translate-x-1`（4px），开启状态继续使用 `translate-x-6`（24px）。
- `w-12` 的 48px 是含 1px 边框的外框；`left-0` 从边框内侧的定位包含块开始。因此白点相对外框的关闭左边缘约为 5px，开启左边缘约为 25px，开启右边缘约为 45px。
- 白点宽 20px，所以两种状态都完整落在 0–48px 的外框范围内；关闭/开启的白点中心分别位于轨道中心左侧和右侧。
- 不改变开关状态逻辑、颜色、尺寸、边框或过渡动画。

## 验证

- 回归测试按独立 class token 检查两个开关白点都具有 `absolute`、`left-0`、`top-1`，不依赖 class 排列顺序。
- 回归测试继续检查关闭为 `translate-x-1`、开启为 `translate-x-6`，并按 48px 外框、1px 边框、20px 白点、4/24px 位移计算两个状态的边界与中心位置。
- 回归测试确认两个控件仍使用原生 `button type="button"`、`role="switch"`、可访问名称和随状态变化的 `aria-checked`；原生按钮继续提供空格键与回车键切换能力。
- 定向测试和 TypeScript 检查通过。

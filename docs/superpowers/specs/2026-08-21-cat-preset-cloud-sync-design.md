# 猫咪预设 CloudBase 跨端同步设计

## 目标

让“预设保存”继续本地即时可用，并可通过同一私密同步码在电脑、手机和不同浏览器间复用。复用项目已有的腾讯 CloudBase 环境，不新增账号系统。

## 方案选择

采用“同步码 + 轻量云函数 + CloudBase 数据集 + 本地优先”。每个同步码对应 `cat_preset_snapshots` 集合中的一个完整预设快照。同步码随机生成；云函数只保存其 SHA-256 摘要作为文档 ID，不保存明文同步码。浏览器不直接读写集合。

不采用手机号/微信登录，因为会引入额外认证配置与 UI；不采用二维码导入导出，因为它不能自动同步。

## 用户界面

在现有“预设保存”区域增加一个紧凑的“跨端同步”行：

- 未连接：同步码输入框、“连接同步”按钮、“生成同步码”按钮。
- 已连接：掩码显示同步码、“复制”、“立即同步”和“断开”按钮。断开只清除本机同步配置，不删除本地或云端预设；更换同步码需先断开再连接。
- 状态只使用短文案：`仅保存在本机`、`正在同步`、`已同步`、`同步失败，本地数据已保留`、`已保存本地，等待联网同步`。

首次生成同步码时自动复制；用户在另一设备输入同一码即可连接到同一份云数据。

## 数据模型

集合：`cat_preset_snapshots`

```js
{
  _id: sha256(normalizedSyncCode),
  version: 1,
  presets: [/* 现有 serializeCatPresets 所允许的预设 */],
  updatedAt: /* CloudBase 服务端时间 */
}
```

整组快照覆盖而非逐条追加，因此删除会随下一次写入直接从云端快照消失，不产生“僵尸预设”。集合只存猫咪外观参数，不存昵称、联系方式或其他敏感信息。

## 同步流程

1. 页面启动先读取 `localStorage`，现有离线行为不变。
2. 本机没有同步码时不加载 CloudBase SDK，不产生网络请求。
3. 生成或输入同步码后，匿名登录 CloudBase，通过 `catPresetSync` 云函数按同步码摘要读取一个文档。
4. 云端不存在文档：上传当前本地预设。
5. 云端存在文档：首次连接以云端快照替换本地快照，并立即刷新列表。
6. 保存、重命名、更新或删除预设时先写本地，同时递增本地修订号并持久化 `dirty: true`，再异步覆盖云端快照；UI 不等待网络。
7. 同一浏览器的云写入使用单一串行队列并合并连续修改。上传成功时，只有待上传修订号仍等于当前修订号才可清除 `dirty`；否则立即继续上传最新快照，避免旧请求覆盖新修改或错误清除待同步状态。
8. 启动或点击“立即同步”时：`dirty: true` 先上传本地快照；`dirty: false` 拉取云端快照。拉取会记录发起时的本地修订号；响应返回时若修订号已变化或已经变为 dirty，则丢弃云端响应并上传最新本地快照，绝不覆盖拉取期间的新编辑。网络失败保留本地数据与 `dirty` 标记，下次启动或手动同步重试。
9. 每次连接或换码生成一个仅驻留内存的连接代次。所有队列任务和异步回调必须携带代次与同步码；断开时递增代次并清空未开始任务，旧代次的迟到响应一律忽略，不得更新预设、状态或新连接的 dirty 标记。

为控制成本，本期采用整组快照和云端最后成功写入优先，不处理两个设备同时离线编辑后的逐条冲突合并。如果两台设备离线期间同时修改，最后恢复联网并上传的设备覆盖云端；这是明确接受的限制。预设上限为 20 条，单文档体积足够小。`updatedAt` 仅供诊断，不参与客户端时钟仲裁。

## 组件边界

- `catPresets.js`：继续负责参数白名单、校验和序列化，不依赖网络。
- 新增 `catPresetCloudSync.js`：负责同步码规范化/生成、CloudBase 初始化、调用云函数和串行合并写入。
- 新增 `cloudfunctions/catPresetSync`：校验同步码和快照，生成文档摘要 ID，并以服务端权限读写单一快照。
- `main.js`：增加少量同步 UI，并在现有 `persistCatPresets` 成功后触发异步云写入。
- `vite.config.js`：让子应用构建读取仓库根目录的 `VITE_TCB_ENV_ID`。

## 安全与部署

CloudBase 匿名身份在不同设备上不同，因此同步码是跨端能力凭证。同步码使用 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` 字符集，由 `crypto.getRandomValues` 生成 20 位（约 100 bit），显示为每 5 位一组。输入时去除空格和连字符并转为大写；其他字符或非 20 位输入均拒绝。任何拿到同步码的人都能读取或覆盖对应猫咪预设，用户不应公开同步码。

部署前需在当前 CloudBase 环境创建 `cat_preset_snapshots` 集合并部署 `catPresetSync` 云函数。集合客户端规则设为 `{ "read": false, "write": false }`，仅云函数以服务端权限访问；函数调用规则允许已登录用户（含匿名登录）调用。云函数只接受 `pull`/`push`，校验同步码格式、预设数组不超过 20 条、字段白名单与序列化体积上限 128 KB，并拒绝其他输入。

本地同步配置持久化在独立的 `localStorage` 键中，包含规范化同步码、`dirty` 和本地修订号。断开时清除此配置并使旧连接代次失效；云端文档保留，之后输入同一码可重新连接。

## 错误处理与兼容

- 缺少 `VITE_TCB_ENV_ID`、CloudBase 不可达或权限不足时，预设仍完整保存在当前浏览器。
- 云端返回非法数据时拒绝覆盖本地，并显示同步失败。
- 未启用同步的旧用户行为完全不变。
- 旧版本本地预设可直接作为首次云端快照上传。

## 测试与验收

- 单元测试覆盖同步码生成/规范化、快照校验、云端为空上传、云端存在下载、网络失败保留本地、删除后整组覆盖、快速连续编辑串行合并、dirty 状态重启上传、clean 状态手动拉取、拉取期间本地编辑、上传期间断开换码以及旧连接响应被忽略。
- 现有预设测试继续通过。
- 生产构建通过并同步到 `public/meow-generator`。
- 手工验收：电脑生成同步码并保存预设；手机输入相同同步码能看到并应用；任一端删除后另一端“立即同步”不再出现该预设；断网保存不会丢失本地预设。

# 留影工坊摄像头拍摄设计

## 目标

在保留本地图片上传的同时，让手机和电脑用户可直接调用设备摄像头拍摄周围环境，并将照片送入现有留影编辑与 PNG 导出链路。实现使用浏览器原生 API，不新增依赖。

## 交互

- “选择一张照片”旁新增“直接拍摄”。
- 点击后打开页内摄像头弹窗；移动设备优先请求后置镜头，电脑使用默认摄像头。
- 弹窗使用明确的 `requesting → live → captured` 状态。请求中禁用重复开启；实时预览提供“拍摄”和“取消”；拍摄后保留冻结帧并提供“使用照片”“重拍”和“取消”。
- “重拍”复用仍在运行的流，不重新请求权限。“使用照片”必须等待现有图片管理器成功载入后再关闭弹窗并重置缩放与位移；失败时保留冻结帧以便重试或取消。
- 取消、确认、错误或离开留影页时，立即停止所有摄像轨道。

## 技术设计

- 使用 `navigator.mediaDevices.getUserMedia({ video: { facingMode: { ideal: 'environment' } }, audio: false })`。
- 视频预览使用带 `autoPlay`、`muted`、`playsInline` 的 `video` 元素及 `srcObject`。只有元数据就绪且 `videoWidth/videoHeight` 均大于零时才允许拍摄；`video.play()` 失败需进入可恢复错误状态。
- 拍摄时按视频原始尺寸绘制到临时 Canvas，再通过 `toBlob('image/jpeg', 0.92)` 生成本地 `File`；缺少 2D context 或返回空 Blob 时显示错误且不改变当前留影照片。
- 拍摄得到的 `File` 复用现有 `createImageResourceManager`，不增加另一套图片读取、拖动或导出逻辑。
- 新增小型摄像头辅助模块，负责能力检测、错误文案、流轨道停止和视频帧转文件；界面只管理弹窗状态。摄像请求使用递增 generation/closed 标记：取消、卸载或新请求会使旧请求失效，之后才返回的流必须立即停止，不能绑定到视频。所有退出路径都停止每条轨道并清空 `video.srcObject`。
- 不保存、不上传视频流或照片，也不请求麦克风。

## 错误与兼容

- 不支持摄像头 API或非安全上下文时显示不可用提示；`NotAllowedError` 映射为权限被拒绝，`NotFoundError` 映射为没有摄像头，`NotReadableError` 映射为摄像头被占用，其余错误使用通用中文提示。所有情况均保留图片上传入口。
- 摄像功能要求 HTTPS 或 `localhost`；关闭弹窗后页面不得继续显示摄像头占用状态。
- 首版不提供前后镜头切换、录像、闪光灯、滤镜或倒计时。

## 验证

- 单元测试覆盖请求参数、能力检测、错误映射、停止全部轨道、空视频帧和 JPEG 文件生成。
- 行为测试覆盖权限延迟返回后取消/卸载、重复开启、每种退出路径、重拍复用原流，以及“使用照片”成功载入并重置视图；界面契约验证入口、三个状态、视频属性和按钮接线。
- 运行相关定向测试、全量测试和 TypeScript 检查；生产构建若再次遇到已知 `esbuild spawn EPERM`，按项目规则停止重试并如实说明。

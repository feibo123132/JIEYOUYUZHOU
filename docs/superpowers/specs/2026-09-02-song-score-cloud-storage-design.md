# 谱子云存储跨端同步设计

## 目标

谱子图片不再以 Base64 塞进云函数和数据库。每页图片上传到 CloudBase 云存储，数据库只保存文件 ID；同一私人档案在不同浏览器和设备登录后都能读取。

## 数据流

1. 图片仍在浏览器端压缩，随后上传到 `song-request-scores/<档案哈希>/<歌曲>/<随机页ID>.jpg`。
2. `songScores:save` 仅保存歌曲信息和云存储 `fileId` 数组。
3. 拉取谱子后，前端批量把 `fileId` 换成临时 HTTPS 地址用于预览和翻谱。
4. 删除谱页或全部谱子时先保存新的元数据，再尽力删除已经不再引用的云文件。
5. 旧本地 Base64 谱子标记为待同步，登录同一档案后自动迁移；失败时保留本地副本并重试。

## 状态与错误

- 本地处理完成但云端未完成：显示“仅保存在本机，等待同步”。
- 图片和元数据都成功：显示“已同步到云端”。
- 拉取失败不再静默吞掉，显示可重试提示。
- 云端是已同步数据的权威来源，本地只保留缓存和待迁移草稿。

## 安全与兼容

- 文件路径不包含明文邮箱，使用档案别称 SHA-256 哈希和随机页 ID。
- 云函数继续用私人档案别称和口令隔离谱子元数据。
- 兼容旧 Base64、旧 HTTPS 谱页和新版 `cloud://` 文件 ID。
- 不修改现有翻谱器手势、长图清晰度和每首歌页数限制。

## 验证

- 纯函数测试覆盖旧数据迁移、显示 URL、增删排序和待同步判定。
- 云适配器源码契约测试覆盖上传、临时 URL、删除和小体积元数据保存。
- 云函数测试确认只接受受限的云文件 ID/HTTPS 引用，不再接受 Base64 入库。
- 运行相关测试、TypeScript 检查和生产构建。

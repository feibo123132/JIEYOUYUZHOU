# Meow Generator 完整引入设计

## 目标

将 GitHub 项目 `ringhyacinth/Meow-Generator` 作为当前网站中的本地、非商业子应用完整引入，并在企划选择首页增加一个风格一致且清晰可发现的入口。访问者点击入口后，应进入本站部署的 Meow Generator，而不是外部 GitHub Pages。

## 已确认约束

- 当前网站及此次集成仅用于非商业用途。
- 保留上游 PolyForm Noncommercial 1.0.0 许可证、Required Notice、作者署名和第三方说明。
- 保留现有两个企划入口、星空背景和当前应用状态逻辑。
- 不覆盖或重写工作区中已有的未提交改动。
- Meow Generator 的 3D、物理、导出、多语言和移动端功能应作为完整子应用保留。

## 集成架构

采用“源码归档 + 独立静态子应用”结构：

1. 将上游仓库固定到 `main` 分支当前提交 `e34483fa7c7fa105618d073444c47adffa69b070`，并把该提交的完整工作树导入 `vendor/meow-generator/`。仅排除上游 `.git` 元数据、依赖安装目录和可重新生成的构建缓存；源码、资源、文档、测试、许可证、`shots/` 和 `third_party/` 均保留。
2. 在仓库中记录上游地址、固定提交、导入日期、许可证和本地构建方式，便于后续审计与同步。
3. 使用上游自身的 Vite 配置和依赖构建子应用，构建时使用相对公共路径，使其可从当前网站的 `meow-generator/` 子目录加载。
4. 将已构建的静态产物保存到 `public/meow-generator/`。当前 React/Vite 主应用构建时会将其原样复制到最终 `dist/meow-generator/`，部署平台无需额外运行第二套安装流程。
5. 首页入口通过普通页面导航进入 `./meow-generator/`。不使用 iframe，避免主站星空 WebGL 与子应用 Three.js 场景同时运行而争夺 GPU、音频和触控资源。浏览器后退可返回企划首页。

该结构把上游应用与现有 React、Tailwind、Three.js 和全局样式隔离，降低版本、CSS 和运行状态冲突，同时保留后续替换固定提交并重新构建的更新路径。

## 首页入口设计

入口位于现有两张企划卡片下方，采用一条横向、紧凑的“猫猫观测舱”入口带，而不是增加第三张同尺寸企划卡片。这样能保留当前双企划的主次关系，并尽量维持截图所示首屏构图。

入口包含：

- 猫爪图标与小型英文标识 `MEOW GENERATOR`；
- 主文案“进入猫猫生成器”；
- 一句简短说明，强调可捏体型、换花色和生成收藏卡；
- 右侧方向箭头，桌面端提供轻微上浮、光晕和箭头位移动效；
- 暖橙为主、薄荷绿为辅的边缘光，与原有紫色和金色卡片区分，同时保持深色半透明玻璃质感。

入口使用原生 `<a>` 链接，具备明确的可访问名称、键盘焦点样式和足够的触控面积。链接指向本站相对路径 `meow-generator/`，在当前标签页打开。移动端改为纵向排布，避免文字和箭头拥挤。遵循 `prefers-reduced-motion` 时取消非必要位移动画。

## 数据与运行边界

Meow Generator 保持原有本地优先、无后端的运行方式。它不读取或修改当前站点的昵称、星星、主题、CloudBase 或 Supabase 数据。其参数与导出文件只保留在浏览器或用户设备中。

主站与子应用之间唯一的数据流是首页入口产生的页面导航；不引入跨应用状态同步，也不新增账号、数据库或分析功能。

## 许可证与来源保留

- `vendor/meow-generator/LICENSE` 和上游商业许可说明必须原样保留。
- 构建输出中固定提供 `public/meow-generator/LICENSE` 与 `public/meow-generator/UPSTREAM.md`；部署后分别可由 `/meow-generator/LICENSE` 与 `/meow-generator/UPSTREAM.md` 直接访问。此次不修改上游子应用 UI 来增加许可证链接，上游应用内原有作者与授权说明保持不变。
- 新增本地说明文件记录上游仓库 URL、固定提交和 Required Notice。
- 不把上游 PolyForm 非商业许可错误标注为 MIT，也不改变其第三方素材声明。

## 测试与验收

实现采用测试优先：

1. 先添加入口契约测试，验证首页存在可访问的 Meow Generator 本地入口，且目标为 `meow-generator/` 子路径而非外部网站。
2. 先添加静态子应用契约测试，验证构建产物入口文件和必要许可证文件存在，再导入与构建上游项目使测试通过。
3. 运行上游现有的分享卡、交互、Motion 等测试，确认完整导入没有破坏原功能。
4. 运行当前项目的定向测试、完整测试、TypeScript 检查和生产构建。
5. 检查最终 `dist/meow-generator/index.html` 及其资源引用，确认部署产物包含可独立加载的子应用。
6. 使用与生产构建一致的本地静态 HTTP 服务访问 `/meow-generator/`、入口 HTML 中引用的至少一个 JS/CSS 资源、`/meow-generator/LICENSE` 与 `/meow-generator/UPSTREAM.md`，要求均返回成功状态且 `/meow-generator/` 返回的是子应用 HTML，而不是主站回退页面。
7. 在桌面和移动宽度下做一次视觉检查，重点验证入口位置、首屏高度、键盘焦点和跳转行为。

## 非目标

- 不把上游 Vanilla JavaScript 应用重写为 React。
- 不重新设计 Meow Generator 内部界面或功能。
- 不建立主站与小猫参数之间的数据同步。
- 不添加商业授权范围之外的品牌或商业用途。
- 不在此次工作中重构现有主题、星空或弹幕模块。

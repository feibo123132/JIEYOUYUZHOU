# 生命万岁企划 100 颗幸福星星设计

## 目标

仅在“生命万岁企划”中新增 100 颗内置、可点击的幸福星星。每颗星星拥有独立昵称、约 50 个汉字的幸福文本、确定的位置，以及暖色系颜色、尺寸和形状；现有用户创建的星星继续正常加载。

## 方案

新增一个纯数据模块，使用固定词组和确定性规则生成 100 条星星数据，并导出唯一的幂等合并函数。`StarrySky` 与欢迎页分别把自己取得的 `life_stars` 在线数据传给该函数；函数按稳定 ID 去重后返回“在线数据 + 内置星星”，因此不会重复加入。JIEYOU 主题原样返回在线数据。内置星星使用 `life-seed-` 前缀的专属 ID 和用户 ID，避免与真实数据冲突。

## 展示与文案

- 形状从星星、爱心、月亮、云朵、树叶、音乐、飞鸟等现有图标中轮换。
- 颜色采用琥珀、金黄、橙色、玫瑰色与暖白色，尺寸保持现有组件支持的 20–36 像素。
- 位置由确定性算法分布在安全范围内，交给现有防碰撞布局做最终调整。
- 每颗文本按 JavaScript Unicode 码点（`Array.from(text).length`，标点和数字均计数）计为 45–55 字，围绕早餐、散步、家人、朋友、宠物、天气、音乐、休息等微小幸福生成；100 条文本与昵称均保持唯一。

## 边界

- 不写入 CloudBase 或 Supabase，不消耗数据库额度，也不改变线上权限。
- 不修改用户每日点亮次数、创建流程及现有搜索、弹幕或详情弹窗组件。搜索会自然检索合并后的内置与真实星星。
- 默认随机模式最多展示 30 颗：优先保留全部真实星星；不足 30 颗时才用随机内置星星补齐。若真实星星本身超过 30 颗，则沿用现有随机抽取 30 颗的行为。
- 欢迎页总数按合并后数量计算；“完整展示”同时渲染全部合并星星；留言模式把全部合并星星作为弹幕候选。
- 内置星星在普通与管理员设备上都不显示删除入口；删除处理器即使被意外调用也必须直接拒绝，不发远程请求且不从当前列表移除。

## 验证

新增定向测试，验证数量恰为 100、ID/昵称/文本唯一、文本长度为 45–55 个 Unicode 码点、字段合法、合并幂等、只对生命主题合并、随机模式优先真实星星，以及内置星星不可删除且不触发远程请求。随后运行相关测试与生产构建。

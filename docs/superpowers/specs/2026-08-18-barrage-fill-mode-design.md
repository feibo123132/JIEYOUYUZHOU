# 弹幕填充模式设计

日期：2026-08-18

## 目标

在助手栏“弹幕”层级下新增独立的“填充模式”。开启后，允许同一条留言在动画层重复出现，并通过首尾相接的循环内容带持续填充每条弹幕轨道，避免当前动画在整组弹幕驶出后出现大面积空白。

该模式只改变横向循环策略，不改变留言数据、搜索结果、现有弹幕模式的页面显隐、亲密模式的横纵间距或轨道安全规则。

## 当前问题

现有每条轨道只有一组按轮询分配的留言。整组内容从视口右侧外移动到自身完全离开左侧后才重新开始下一轮。轨道内容较短、留言数量较少或屏幕较宽时，内容带会整体离开可视区域，而下一轮尚未进入，因此同一时刻可能有多条轨道在右侧留下大片空白。

单纯缩短动画时长或增加固定复制次数不能稳定解决问题：前者只会让空白更快经过，后者在超宽屏或极短内容下仍可能不足。

## 用户界面与状态

- 在助手栏“弹幕”折叠内容中，于“亲密模式”下方增加第三个同款开关。
- 名称为“填充模式”，说明文字为“循环补齐弹幕，减少屏幕空白”。
- 开关使用现有 `role="switch"`、`aria-checked`、关闭在左和开启在右的视觉规范。
- 填充模式是独立布尔偏好，可与弹幕模式、亲密模式任意组合。开启填充模式不自动开启弹幕模式，也不强制切换版面。
- 状态沿用当前弹幕偏好的会话级生命周期；切换主题时与另外两个弹幕偏好一起恢复关闭，不写入本地或云端存储。

## 无缝填充策略

### 轨道分组

留言仍按现有轮询规则分配到桌面端或移动端轨道。亲密模式继续决定轨道数量、纵向安全间距和胶囊之间的横向间距。填充模式不新增轨道，也不重新排序原始留言集合。

为了避免各轨道显示完全相同的起点，每条轨道保留现有基于轨道序号的负延迟；一条轨道内的重复顺序保持稳定，不在每次 React 渲染时随机变化。

### 填充单元

每条非空轨道先生成一个“基础序列”，即该轨道拥有的全部留言各一次。设：

- `W` 为当前可见弹幕舞台宽度；
- `B` 为基础序列所有胶囊及其内部间距的实测总宽度，不包含序列末尾间距；
- `G` 为当前模式下一个胶囊横向间距换算后的实测像素值；
- `n` 为一个循环单元内基础序列的重复次数；
- `U` 为一个循环单元的最终宽度。

每份基础序列末尾都保留一个 `G`，包括循环单元的最后一份，因此 `U = n × (B + G)`。重复次数使用唯一公式：

`n = max(1, ceil(W / (B + G)))`

该公式保证 `U >= W`，且 `n` 是满足条件的最小整数。`W` 与 `B` 必须是有限正数，`G` 必须是有限非负数；初次测量或任一测量无效时回退为 `n = 1`，随后在 `useLayoutEffect` 的有效测量中更新。窗口宽度、断点、字体或胶囊尺寸、留言集合、轨道数量以及模式变化时重新测量。

### 首尾衔接

动画轨道渲染两个内容完全相同、宽度均为 `U` 的循环单元。两个单元无额外外部间距地相邻排列，单元内部最后一份基础序列的尾部 `G` 同时充当两个单元之间的衔接间距。

填充动画不沿用普通动画的 `100vw` 入场起点。轨道从 `translate3d(0, -50%, 0)` 匀速移动到 `translate3d(-50%, -50%, 0)`；由于整个轨道恰好由两个等宽单元组成，横向 `-50%` 等于 `-U`。到达终点后复位到起点时，第二个单元所显示的画面与第一个单元起始画面完全一致，因此不会出现普通模式中“整带完全离场后再从右侧进入”的空窗。

每条轨道继续使用基于轨道序号的现有负延迟。填充动画以 `60px/s` 为目标速度，唯一时长公式为 `clamp(24s, U / 60px, 90s)`：即先计算 `U / 60` 秒，再限制在 24 至 90 秒之间。这样常见宽度下速度稳定，同时避免极短或极长循环单元产生异常时长。测试需直接覆盖下限、中间值和上限三个区间。

重复节点的 React key 必须稳定且在同一兄弟集合中唯一，至少由 `循环单元序号 + 基础序列重复序号 + 留言 ID + 留言在基础序列中的位置` 组成。不得只使用留言 ID，以免重复副本产生 key 冲突或错误复用。

填充模式关闭时，继续使用现有单内容带及 `barrage-travel` 动画，保证普通模式行为不变。

## 组件边界与数据流

- `barragePreferences.ts` 增加 `fill` 布尔字段；初始化和通用 `setBarragePreference` 继续保持纯函数接口。
- `StarrySky.tsx` 从偏好状态派生 `fillMode`，向侧栏传递值和切换回调，并将 `fill` 传给 `MessageBarrage`。
- `AssistantSidebar.tsx` 只渲染开关并通过回调更新状态，不保存第二份本地状态。
- `barrageLayout.ts` 增加可独立测试的纯计算函数，根据舞台宽度、基础序列宽度和衔接间距返回最小重复次数；非法测量回退为 1。
- `MessageBarrage.tsx` 负责渲染基础序列测量目标、监听尺寸变化、调用纯计算函数，并仅在填充模式下切换为双循环单元结构。
- `index.css` 增加填充轨道结构和无缝位移动画；现有普通动画保留。

测量监听复用当前 `ResizeObserver`、窗口 `resize`、移动端断点与减少动态偏好监听的生命周期模式。所有请求的动画帧、事件监听和观察器必须在依赖变化或组件卸载时清理，且状态值未变化时不重复更新。

## 边界与性能

- 没有留言时继续显示现有空状态，不创建填充轨道。
- 单条留言会在其所属轨道内按需重复，允许同一条留言同时出现多次。
- 每条轨道仅渲染满足一屏所需的最小重复次数，再复制一次循环单元；不使用任意固定的大量副本。
- 基础序列宽于舞台时重复次数为 1，仍通过两个循环单元实现首尾连接。
- 两个响应式轨道集合可以同时存在 DOM 中，但只使用当前可见集合的有限正数测量值，忽略 `display: none` 产生的 0 宽度。
- 搜索导致留言减少、同数量留言替换、亲密模式改变轨道数或窗口缩放时，当前轨道 DOM 会重新绑定观察并重新计算。

## 可访问性与减少动态效果

- 动画轨道继续使用 `aria-hidden="true"`，重复副本不会被辅助技术重复朗读。
- 完整静态留言列表仍是唯一的可访问内容来源。
- `prefers-reduced-motion: reduce` 下继续隐藏所有动画轨道并显示现有静态列表；填充模式不复制静态列表内容，也不强制播放动画。
- 舞台的可访问名称、`tabIndex` 和聚焦暂停行为保持不变；悬停或聚焦舞台时，填充轨道也应暂停。

## 验证

1. 纯函数测试覆盖：基础序列短于舞台、恰好等于舞台、宽于舞台、单条极短弹幕、有限值临界点，以及 0、负数、`NaN`、无穷等非法测量。
2. 证明循环单元宽度 `U` 不少于舞台宽度 `W`，并且重复次数是满足 `U >= W` 的最小整数。
3. 组件接线测试覆盖第三个开关、关闭/开启白点位置、独立状态、主题切换复位，以及 `StarrySky` 到 `MessageBarrage` 的属性传递。
4. 渲染契约测试覆盖两个相同循环单元、稳定顺序、填充专用类名、普通动画保留和填充关闭时不渲染副本；同时明确断言填充动画使用 `0 → -50%` 位移且不引用普通动画的 `100vw` 入场起点。
5. 测量生命周期测试覆盖首次同步测量、`ResizeObserver`、窗口缩放、640px 断点、留言替换、亲密模式轨道重分组、动画帧合并与完整清理。
6. 组合验证覆盖普通间距 + 填充、亲密间距 + 填充、弹幕模式 + 填充，以及减少动态效果。
7. 定向测试、TypeScript 检查和生产构建通过。

## 非目标

- 不改变或重复底层留言数据，不向数据库写入副本。
- 不增加随机弹幕、优先级、用户屏蔽或新速度设置。
- 不重构星星布局、搜索、创建、删除或主题数据逻辑。
- 不承诺每个像素始终被胶囊覆盖；目标是让每条非空轨道的内容带连续循环，消除整段离场造成的大面积时间性空窗。

# 答题用户名同步昵称设计

## 目标

用户每次在听歌识曲中点击“开始答题”时，将去除首尾空格后的用户名同步为欢迎页两个星星入口的昵称初始值，并在刷新或重新打开页面后继续保留。

## 方案

- 新增独立的昵称本地存储模块，统一负责读取和写入，避免答题组件与欢迎页直接共享用户身份对象。
- `RecognitionSongListEditor` 在每次成功开始答题时写入最新用户名。
- `NicknameInput` 初始化时优先采用已同步用户名，其次采用现有用户昵称。
- 同步值按答题输入规则处理：去除首尾空格后，原样保存 1–24 个字符，不过滤内部空格、标点或 emoji；欢迎页仍执行原有昵称校验，需要时提示用户修改。
- “无效存储数据”仅指缺失值、非字符串结果或去除首尾空格后为空；此时回退到现有用户昵称。
- 本地存储不可用时静默降级，不阻断答题与星星入口。
- 不改变现有用户名长度限制、昵称提交校验、答题计分和云同步行为。

## 验证

- 单元测试覆盖空值忽略、首尾空格清理、重复覆盖、读取，以及标点或 emoji 原样保留。
- 接入测试覆盖同步值优先、现有用户昵称回退。
- 源码接入测试确认“开始答题”写入以及欢迎页输入框读取。
- 运行相关定向测试，再运行完整测试套件。

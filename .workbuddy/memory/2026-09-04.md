## 星空树洞：管理员模式二次编辑所有星星

用户需求：管理员模式（`isAdminDevice`）下具备二次编辑所有星星的权利，两个企划（jieyou / life）都要支持。

### 实现思路
星星的删除权限原本就是 `star.userId === userId || isAdminDevice`，管理员已可删除所有星星。本次在删除旁边新增"编辑"按钮，管理员点击后弹出与创建星星相同的表单（预填充当前值），修改后调用新的 `updateStar` API 更新。

### 修复：编辑星星时保留原文
- **问题**：点击"编辑"后，模态框的留言 textarea 为空，没有预填星星原本的文字内容。
- **根因**：`CreateStarModal` 使用 `if (!open) return null` 条件渲染，React 不会真正卸载组件实例；再次打开时 `useState` 不会重新读取新的 `initialData`，导致 `message` state 残留旧值或为空。

- **文件**：`StarrySky.tsx`（仅新增一行 `key` prop）。

### 一键导入 bug 修复

  1. **去掉去重**（`SongRequestStation.tsx`）：导入时直接将 `ranking` 全部 `createRoadshowSong` 后追加到 `latest.performanceSongs`，每次点击都真实写入云端；如需管理重复歌曲，可走路演歌曲的「歌曲编辑 → 清空全部」。

  3. **RoadshowPanel 监听该事件**（`RoadshowPanel.tsx`）：收到事件后重新拉取云端路演，更新 `records` 状态；若当前 `editing` 对应同一 `id`，同步把 `editing` 替换为最新云端版本（解决「回到路演页还看到 0 首」的缓存陈旧问题）。
- **验证**：`tsc -b --noEmit` 通过；`tests/songOrder.test.ts` 5/5 通过。
- **需求**：把原来在助手栏的"星语心愿"按钮迁移到星空主界面底部操作区域（"点亮星星"按钮旁边），改名为"星星之家"。

### 修复：一键导入后路演歌曲看不到新歌
- **现象**：点「一键导入」提示成功 N 首，切回路演歌曲页却看不到导入的歌。
- **根因**：① 导入逻辑按 catalogId/title+artist 去重判断有偏差，可能把歌曲误判为"已存在"而全部跳过 → 干脆**去掉去重**，每次点击直接把已点歌曲全部追加；② 即使数据已保存到云端，`RoadshowPanel` 的 `editing` 编辑态初始值是从 `ROADSHOW_EDITING_KEY`(localStorage) 恢复的**旧快照**，导入发生在 RoadshowPanel 卸载期间时事件监听收不到 → 重挂载后仍显示旧歌单。
- **修改**（`SongRequestStation.tsx` + `RoadshowPanel.tsx`）：
  - `SongRequestStation.tsx`：移除 existingIds 去重过滤，`additions = ranking.map(({ song }) => createRoadshowSong(song))` 全量追加；保存成功后 `window.dispatchEvent(new CustomEvent('jieyou-roadshow-imported', { detail: { recordId: saved.id } }))`。
  - `RoadshowPanel.tsx`：
    1. 新增 `jieyou-roadshow-imported` 事件监听：收到后重拉云端，若 `editing.id === recordId` 则 `setEditing(云端最新)`（实时场景）。
    2. 主 `pullRoadshows` effect 的 then 中做**云端权威覆盖**：用 `editingRef.current` 读取当前编辑态，若云端同 id record 的 `updatedAt > 本地快照`，则 `setEditing(cloudRecord)`（覆盖"卸载期间导入、回来重挂载"场景）。注意 `setEditing` 是自定义 wrapper（同步写 ROADSHOW_EDITING_KEY），**不接受函数式更新**，需配合 `editingRef = useRef(editing)` + effect 同步。
- **验证**：`tsc -b --noEmit` 通过；`tests/songOrder.test.ts` 5/5 通过。

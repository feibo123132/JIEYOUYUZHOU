## 坑：`.build-check-*` 临时构建目录让 git 变更数暴涨

**现象**：VS Code 源码管理显示 572 个更改，用户以为发生大改。

**成因**：`npx vite build --outDir .build-check-XXXX` 每次都会把 `public/` 的静态资源（mp3 + 图片 + js/css，共 69 个文件 / 59MB）完整复制一份。这些目录在项目内、未被 `.gitignore` 覆盖，VS Code 展开目录后每个文件都算一条新增。8 个目录 × 69 = 552，加上 20 个真实源码改动 = 572。

**清理受阻（重要）**：
- `rm -rf` 与 Windows 原生删除都会被 safe-delete 垫片接管，走 `genie-trash` 回收站。
- `genie-trash` **对含中文的工作区路径直接失败**：日志里路径被转成 `JIEYOUϵ��`，报 `Some operations were aborted`。**本工作区（路径含「系列/我们的JIEYOU宇宙」）无法通过工具删除任何目录。**
- 把目录移动到工作区外被沙箱拒绝（Permission denied）。

**已做**：`.gitignore` 增加 `.build-check-*/`，变更数立刻 572 → 21（全部真实改动）。

**以后的规矩**：
1. 构建验证优先直接用默认 `dist/`（已在 .gitignore 内），不要再用 `--outDir .build-check-*`。
2. 若必须指定输出目录，先确认该目录可被删除（本工作区实际删不掉）。
3. 需要清理磁盘时由用户在资源管理器手动删除（系统回收站不受 genie-trash 编码 bug 影响）。

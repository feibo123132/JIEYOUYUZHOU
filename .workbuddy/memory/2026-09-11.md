## 修复：谱子（点歌台 → 我的档案 → 谱子）放久了变裂图，必须刷新页面才恢复

**现象**：iPad / 电脑（localhost 与 GitHub Pages 均复现）打开谱子后，过一段时间所有谱子图片变成裂图（列表缩略图 + 翻谱器全黑只有裂图图标），刷新整个网页后又完整显示。

**根因**：谱子图片存在腾讯云存储，`<img>` 用的是 `tcbApp.getTempFileURL({ maxAge: 86400 })` 换来的**签名临时地址，带有效期**。原实现只在「拉取云端数据」那一次 `useEffect` 里换链接，之后：
- SPA 里切页 / 重新挂载对应组件 → `<img>` 用内存里那份已经过期的地址重新请求 → 裂图；
- `saveSongScoreCache` 还把换好的签名地址一起写进了 localStorage，冷启动会先拿旧地址渲染。
两种情况下都没有任何重新换链的机制，只能整页刷新（重新跑一次 pull）才恢复。

**修复（4 处）**：
1. `songRequestCloud.ts`
   - 新增导出 `refreshSongScorePageUrls(pages)`：按需重新调用 `getTempFileURL`（先 `ensureSignIn`），非 cloud 页面原样返回。
   - `pullSongScores` 不再用 `pageUrls?.length === pages.length` 这个捷径信任已存地址，只要含 `cloud://` fileID 就一律重新换取（签名地址天然有有效期，不能沿用旧链接）。
2. 新增 `src/components/SongRequest/useResolvedScorePages.ts`（自愈 Hook）
   - 挂载 / 切歌 / 回到前台（`visibilitychange`+`focus`）/ 网络恢复（`online`）/ 每 15 分钟定时检查时换链；返回可直接给 `<img>` 的 `pages` 与 `refresh(force)`。
   - 节流：主动换新阈值 2h、回到前台阈值 20min；`busyRef` + `pendingRef` 串行化，`generationRef` 世代号防止「切歌时上一首的在途结果贴到新歌上」。
   - `onError` 重试：合并同一批失败、延迟 1.2s 换新重试，连续失败上限 4 次（`force` 可越过），地址没变化时不重置计数，避免坏图死循环。
   - 重试标记用 URL `#score-retry=N` 片段：不参与 COS 签名校验，但能强制浏览器重新发请求。
3. `SongDetailPanel.tsx`
   - 在早返回 `if (!session)` **之前**调用 Hook（Rules of Hooks），`scorePages` 改为 Hook 输出（初值仍取 `getSongScoreDisplayPages(score)` 以保证首屏立即有色）。
   - 缩略图 `<img onError={() => refreshScorePages()}>`。
4. `ScoreViewer.tsx`
   - 新增 `onPagesStale?: (force?: boolean) => void`；`<img>` 加 `onError`（标记失败 + 通知换链）与 `onLoad` 清除失败态；`page` 变化时重置失败态。
   - 底部提示在失败时替换为「谱子加载失败，点此重新加载」按钮（`onPagesStale(true)`）。

# 2026-10-30

## 新增「狂扫指数」+ 独立狂扫榜 + BPM 数字填空

在「合唱指数」那套范式上再做一份，三者（匹配度 / 合唱指数 / 狂扫指数）共用 70–100 刻度与同一套品质分档。

**字段（`songRecords.ts`）**
- `PracticeRecord.strumScore?: number`（狂扫指数，70–100 整数，缺省=没评）
- `PracticeRecord.strumBpm?: number`（狂扫速度，**20–300** 整数，缺省=没填）
- 常量 `STRUM_BPM_MIN = 20` / `STRUM_BPM_MAX = 300`，前端与云函数各有一份，改范围必须同时改。
- `bestStrumScore()`：取多次练习最高分（同 bestChorusScore 写法）。
- `bestStrumBpm()`：**BPM 跟着最高分那次走**（同分取更晚一次），刻意不做「最近一条」，否则榜单会出现「A 的分 + B 的速度」。没有狂扫指数的记录不贡献 BPM。
- `rankSongsByPracticeMatch()` 输出新增 `strumScore` / `strumBpm`；`PublicPracticeRankingItem` 新增同名字段，`parsePublicPracticeRanking()` 把云端 0 值容错成 `null`。
- `cleanSongRecord()` 落盘前过滤非法值与越界 BPM。

**练习表单（`SongDetailPanel.tsx`）**
- 新增第三行网格：`狂扫指数（70–100） | BPM | 品质`。BPM 放在指数右侧（用户要求「旁边」），品质留在最右列，与上两行的品质列垂直对齐。
- `strumQuality = getMatchQuality(Number(strumScore))`；指数与 BPM 都走 `parseMatchScoreInput`（`'' → ''`，否则 Number）。
- 保存前分别校验：指数 70–100 整数、BPM 20–300 整数；错误提示分开写给用户看。
- 保存后一致性检查加入 `strumScore` / `strumBpm`，未同步时提示「优点勾选、合唱指数或狂扫指数未同步」。
- 记录卡片用新抽的 `ScoreBadge` 组件渲染（合唱/狂扫共用），BPM 单独一行 `BPM 128`。

**榜单（`songRequest.ts` / `SongRequestStation.tsx`）**
- `PracticeBoard` 扩成 `'practice' | 'chorus' | 'strum'`。
- 侧栏原来 `flex gap-2` 两个按钮改成 `grid grid-cols-3`，新增「狂扫榜」（再点一次回练习榜，逻辑同合唱榜）。
- 排序：狂扫指数降序 → 并列用匹配度兜底；未评（null）沉底。
- 行内渲染：`品质 + BPM + 狂扫指数`；`personalBoardLabel` / `personalBoardNoun` 增加 strum 分支，空状态文案「还没有狂扫记录」。

**云端（`songRequestSync`）**
- `validation.js`：新增 `STRUM_BPM_MIN/MAX` 常量、`strumScore`(70–100) 与 `strumBpm`(20–300) 校验，sanitize 输出带上两字段。
- `index.js` `buildPublicPracticeRanking()`：分组累加 `strumScore` 最高值；BPM 用 `strumBpmScore` / `strumBpmAt` 辅助字段实现与前端一致的「跟最高分走」；输出 `strumScore` / `strumBpm`（无则 0，前端容错成 null）。

## Bug 修复：JSX 标签不匹配 + paginateRoadshowSongs undefined 错误

### 问题1：SongRequestStation.tsx JSX 语法错误
- 搜索直达歌曲功能引入的深层 Fragment 嵌套（`<>`/`</>` 四层嵌套）导致 Vite/SWC 解析失败，浏览器报 "Expected corresponding JSX closing tag for `<>`"。

- `paginateRoadshowSongs` 接收的 `songs` 参数可能为 `undefined`（当 `record.performanceSongs` 未定义或分组结果异常时），导致 `songs.length` 抛 `Cannot read properties of undefined`。
- **修复**：`paginateRoadshowSongs` 参数类型改为 `T[] | undefined`，函数内部加 `const safeSongs = songs ?? []` 兜底，后续操作全部基于 `safeSongs`。

## 路演歌曲「从歌库添加」加入后立即保存

### 问题
选歌器点击「加入」后仅更新了 `editing.performanceSongs` 编辑态，未调用 `persistRecord()` 保存到 localStorage，刷新页面后添加的歌曲丢失。

### 第一次修复（仍有 bug）
- `SongListEditorProps` 新增 `onSave?: () => void`；「加入」按钮先 `onChange` 再 `onSave?.()` 立即持久化。
- **根因未解**：React 状态异步更新，`persistRecord` 默认读取闭包中的 `editing` 仍是旧值，保存的是不含新歌曲的数据。

### 第二次修复（彻底解决）
- `SongListEditorProps.onSave` 改为 `(updatedSongs: RoadshowSong[]) => void`，点击「加入」时传入更新后的歌曲列表。
- `EditorProps.onSave` 改为 `(candidate?: RoadshowRecord) => void`，`RoadshowEditor` 内 `SongListEditor` 的 `onSave` 包装为：构造完整 `{ ...record, performanceSongs: updatedSongs }` 后传给外层 `onSave(candidate)`。
- 外层调用改为 `onSave={(candidate) => void persistRecord(candidate ?? editing)}`，确保收到 candidate 时立即保存最新状态。
- 底部「保存到云端」按钮的 `onClick` 改为 `() => onSave()`，避免类型不兼容。
